# DESIGN.md · 产品与情绪设计

> 定位：**私人的情绪倾诉对象**——先自用，后小圈子。成功标准是主观感受（被接住 / 被记得 / 愿意再回来）。
> 执行计划见 `TODO.md`；具体数值（尺寸、时长、参数）以代码为准。

## 一、边界

- 只做倾诉：不是工作助手、不是心理治疗师。
- 记忆是核心资产：用户回来是因为"它记得我"。
- 情绪是关系的表达，不是每轮表演。

| 阶段 | 用户 | 形态 | 约束 |
|---|---|---|---|
| 现在 | 自己 | 本地单用户 | 数据不出本机、可清空 |
| 之后 | 小圈子 | 一机多 userId | 隔离、访问控制、成本 |

## 二、产品原则

1. **先接住，再回应**：不急着分析、评判、给建议。
2. **倾听优先于推进**：不每轮追问；允许短回复和沉默。
3. **记忆只记"人、事、情绪模式"**：不记流水账。
4. **表达稀疏、高信号**：只在状态显著变化时出现。
5. **不扮演治疗师**：不诊断、不承诺治愈；危机内容引导现实支持。
6. **记忆可见、可遗忘**。

## 三、情绪模型

```
用户消息
  → ① 感知：独立 flash 分类器 → affect（用户情绪 + 强度）
  → ② 关系：relation_state（familiarity / trust / warmth，慢变量）
  → ③ 表达：presence（页面表情 + 强度），只在高强度时放大
```

不是 AI 自报情绪，而是"读懂用户 → 共情反应"。正文不携带任何情绪标记。

### 为什么放弃旧 mood

旧方案由主模型在正文里打 `⟦mood:X⟧`：每轮强制、与内容争注意力、非思考模式命中率低，第二个情绪会立即抢占第一个（"愤怒一闪而过"）。现方案把感知从生成里拆出来，输出侧只保留一次 presence。

### 词表与强度

6 词：平静 / 愉快 / 好奇 / 难过 / 愤怒 / 困惑。
强度 1–5：低强度只更新 dock；高强度才 spotlight。具体阈值、尺寸、停留时长在代码/CSS。

### 共情映射

| 用户 | 显示 |
|---|---|
| 难过 / 愤怒 / 愉快 / 好奇 / 困惑 | 同名表情 |
| 焦虑、紧张 | 平静或难过（稳定承接，不跟着慌） |
| 平静 | 平静（关系基调） |

刷新/切锚用 `anchor.lastExpression` 恢复，按低强度处理（不放大）。

### 关系状态

`familiarity` 随对话次数/深度缓慢增长；`trust` 在用户披露脆弱且回应得当时增长；`warmth` 是近期情绪滑动平均。目前只累计，后续用于语气松紧与主动关心。

## 四、对话原则（Wave 1 目标）

- 默认短回复（2–4 句），能一句说清就一句；用户要求展开才分层。
- 不写小标题、不列清单、不写总结段。
- 不每轮追问；需要时只问一个具体问题。
- 用户要建议时，只给一个最小可执行动作。
- 不做诊断；自我否定/危机内容先共情，再建议现实支持。
- 记忆引用每场最多一次，且必须与当前话题相关。

## 五、记忆策略

- 优先级：情绪事件 > 关系事件 > 普通事实。
- 重要经历记录：`发生了什么 → 当时什么感受 → 什么起了作用`。
- 画像重点：触发点 / 安抚方式 / 在意什么 / 忌讳什么。
- 召回优先"情绪相似"与"同一人/同一事"，其次语义相似。
- 长对话超窗压缩，而不是直接丢弃。
- 记忆可查看、可要求"忘掉这个"。

## 六、不做

- MySQL + R2DBC（暂缓）、Skills / Artifact（生产力向）
- 工具调用合并（会被后台抽取取代）
- 旧数据库迁移（删库重建）
- 每轮情绪标签 / AI 自报心情

## 七、已知取舍

- 分类器串行在 prepare，首字有额外延迟；计划与 embed/recall 并行。
- 刷新只恢复表情，thinking/工具卡暂不恢复。
- 关系状态只写不读。
